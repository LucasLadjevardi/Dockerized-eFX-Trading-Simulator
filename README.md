# Dockerized eFX Trading Simulator

A Dockerized electronic foreign exchange trading simulator built with **ASP.NET Core**, **React**, **SignalR**, **Redis**, **PostgreSQL**, **Nginx**, and **Docker Compose**.

The application simulates a simplified eFX workflow: live FX prices are generated by the backend, streamed to the frontend, quoted to the user, atomically executed as mock trades, checked against pre-trade risk limits, stored durably in PostgreSQL, and reflected in live positions and unrealized P&L.

This project is intended as a learning and portfolio project for understanding common concepts used in electronic trading systems. It is not connected to real markets and does not place real trades.

---

## Features

- Simulated live FX prices for common currency pairs
- Real-time price streaming with SignalR
- React dashboard with live price board and price chart
- Quote request workflow using bid/ask pricing
- Temporary executable quotes with Redis expiry
- Atomic single-use quote execution
- Mock trade execution
- Durable trade history stored in PostgreSQL
- Position tracking by FX pair
- Unrealized P&L calculation
- Realized P&L calculation
- User-specific portfolio scoping through `X-Portfolio-Id`
- P&L chart and exposure summary cards
- Rule-based pre-trade risk checks
- Docker health checks for frontend, backend, Redis, and PostgreSQL
- Dockerized frontend, backend, Redis, and PostgreSQL services
- Nginx frontend container with API and SignalR proxying
- Swagger UI for backend API exploration
- Optional CI/CD workflows for build validation and Docker image publishing

## Supported Currency Pairs

The simulator currently generates prices for:

- `EURUSD`
- `GBPUSD`
- `USDJPY`
- `EURGBP`

Currency pairs are interpreted using standard FX convention:

```text
EURUSD = EUR / USD
Base currency = EUR
Quote currency = USD
```

A trade amount is treated as the **base currency amount**.

Example:

```text
BUY 1,000,000 EURUSD at 1.0850
= buy 1,000,000 EUR
= sell 1,085,000 USD
```

## Architecture Overview

```text
React Frontend
    |
    | HTTP requests: quotes, trades, positions, history
    | SignalR: live prices and position updates
    v
Nginx Frontend Container
    |
    | /api/*   -> backend:8080/api/*
    | /hubs/*  -> backend:8080/hubs/*
    v
ASP.NET Core Backend
    |
    |-- PriceGeneratorService
    |-- QuoteService
    |-- ExecutionService
    |-- TradeService
    |-- PositionService
    |-- RiskService
    |-- PriceHub SignalR hub
    |
    |-- Redis: prices, quotes, positions, locks
    `-- PostgreSQL: durable trade history
```

The frontend is served by Nginx on host port `3000`. Nginx proxies API requests and SignalR WebSocket traffic to the backend service inside the Docker network.

The backend exposes REST endpoints and a SignalR hub. Redis stores latest prices, price history, temporary quotes, portfolio-scoped positions, and short-lived execution locks. PostgreSQL stores portfolio-scoped filled trade history.

## Runtime Services

Docker Compose starts four services:

| Service | Description | Host Port |
|---|---|---:|
| `frontend` | React app served by Nginx | `3000` |
| `backend` | ASP.NET Core API and SignalR hub | `8080` |
| `redis` | Redis data store | `6379` |
| `postgres` | PostgreSQL trade store | `5432` |

## Setup

### Prerequisites

Install:

- Docker
- Docker Compose

You do not need to install .NET, Node.js, Redis, or PostgreSQL locally if running through Docker.

### Running the application

From the repository root, run:

```bash
docker compose up --build
```

Then open:

```text
Frontend: http://localhost:3000
Backend:  http://localhost:8080
Swagger:  http://localhost:8080/swagger
Health:   http://localhost:8080/health
```

To stop the application:

```bash
docker compose down
```

## SignalR

The backend exposes a SignalR hub at:

```text
/hubs/prices
```

The frontend subscribes to:

```text
pricesUpdated
positionsUpdated
```

`pricesUpdated` is broadcast when the background price generator creates a new tick.

`positionsUpdated` is broadcast when positions exist and are recalculated against latest prices.

## Redis Data Model

Common keys:

```text
price:EURUSD
pricehistory:EURUSD
quote:{quoteId}
portfolio:{portfolioId}:position:{pair}
lock:execution:portfolio:{portfolioId}:pair:{pair}
lock:execution:portfolio:{portfolioId}:risk
```

Redis uses append-only persistence in Docker Compose. Filled trades are stored in PostgreSQL rather than Redis.

See [Redis Data Model](../../wiki/Redis-Data-Model) for details.

## Execution and Risk

Quote execution is single-use. The backend atomically claims a quote before filling a trade, so a quote cannot be executed twice.

Execution uses short-lived Redis locks:

- a per-portfolio, per-pair lock to protect position updates for the same currency pair
- a per-portfolio risk lock to protect cross-pair risk checks

The risk service applies rule-based pre-trade checks against the projected post-trade portfolio:

```text
Max single trade size: 2,000,000 base currency units
Max pair net exposure: 5,000,000 base currency units
Max currency exposure: 7,500,000 USD equivalent
Max gross notional: 15,000,000 USD
Max unrealized loss: 100,000 USD
Market prices must be fresh
```

These are defaults from `backend/appsettings.json` and can be overridden with configuration or environment variables.

The simulator allows both long and short positions, which is common in institutional FX workflows.

## Known Limitations

This is a simplified simulator. Current limitations include:

- Prices are randomly generated and not connected to real market data.
- Redis is still used for fast simulator state; Redis persistence is enabled in Docker Compose, while filled trades are stored durably in PostgreSQL.
- There is no authentication or user separation.
- All users share the same simulated trading state.
- Risk checks are simplified and intended for educational use.
- P&L calculations are simplified and do not handle all real-world FX accounting cases.
- There is no real FIX connectivity or external liquidity provider integration.
