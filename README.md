# Dockerized eFX Trading Simulator

A Dockerized electronic foreign exchange (eFX) trading simulator built with **ASP.NET Core**, **React**, **SignalR**, **Redis**, **Nginx**, and **Docker Compose**.

The application simulates a simplified FX trading workflow: live FX prices are generated by the backend, streamed to the frontend, quoted to the user, executed as mock trades, checked against basic risk limits, stored in Redis, and reflected in live positions and unrealized P&L.

This project is intended as a learning and portfolio project for understanding common concepts used in electronic trading systems. It is not connected to real markets and does not place real trades.

---

## Features

- Simulated live FX prices for common currency pairs
- Real-time price streaming with SignalR
- React dashboard with live price board and price chart
- Quote request workflow using bid/ask pricing
- Temporary executable quotes with Redis expiry
- Mock trade execution
- Trade history stored in Redis
- Position tracking by FX pair
- Unrealized P&L calculation
- Basic risk checks
- Dockerized frontend, backend, and Redis services
- Nginx frontend container with API and SignalR proxying
- Swagger UI for backend API exploration

---

## Supported Currency Pairs

The simulator currently generates prices for:

- `EURUSD`
- `GBPUSD`
- `USDJPY`
- `EURGBP`

Currency pairs are interpreted using standard FX convention:

```text
EURUSD = EUR / USD
Base currency = EUR
Quote currency = USD
```

A trade amount is treated as the **base currency amount**.

Example:

```text
BUY 1,000,000 EURUSD at 1.0850
= buy 1,000,000 EUR
= sell 1,085,000 USD
```

## Architecture Overview

```text
React Frontend
    |
    | HTTP requests: quotes, trades, positions, history
    | SignalR: live prices and position updates
    v
Nginx Frontend Container
    |
    | /api/*   -> backend:8080/api/*
    | /hubs/*  -> backend:8080/hubs/*
    v
ASP.NET Core Backend
    |
    |-- PriceGeneratorService
    |-- QuoteService
    |-- TradeService
    |-- PositionService
    |-- RiskService
    |-- PriceHub SignalR hub
    v
Redis
```

The frontend is served by Nginx on port `3000` on the host machine. Nginx proxies API requests and SignalR WebSocket traffic to the backend service inside the Docker network.

The backend exposes REST endpoints and a SignalR hub. Redis stores the latest prices, price history, temporary quotes, trades, and positions.

## Runtime Services

Docker Compose starts three services:

| Service | Description | Host Port |
|---|---|---:|
| `frontend` | React app served by Nginx | `3000` |
| `backend` | ASP.NET Core API and SignalR hub | `8080` |
| `redis` | Redis data store | `6379` |


## API Overview

### Health Check

```http
GET /health
```

Returns backend and Redis connectivity status.

---

### Prices

```http
GET /api/prices
```

Returns the latest generated prices for supported FX pairs.

```http
GET /api/prices/history/{pair}
```

Returns recent historical price ticks for a pair, used by the frontend chart.

Example:

```http
GET /api/prices/history/EURUSD
```

---

### Quotes

```http
POST /api/quotes
```

Creates a temporary executable quote.

Example request:

```json
{
  "pair": "EURUSD",
  "side": "BUY",
  "amount": 1000000
}
```

The amount is interpreted as the base currency amount.

For a buy order, the quote uses the ask price. For a sell order, the quote uses the bid price.

Quotes are stored in Redis with an expiry time and cannot be executed after expiry.

---

### Trades

```http
POST /api/trades
```

Executes a quote if it still exists and passes risk checks.

Example request:

```json
{
  "quoteId": "q-example-id"
}
```

If successful, the backend creates a trade, stores it in Redis, deletes the quote key to prevent double execution, and updates the position.

```http
GET /api/trades
```

Returns recent trade history.

---

### Positions

```http
GET /api/positions
```

Returns all open positions.

```http
GET /api/positions/{pair}
```

Returns the position for a specific pair.

Example:

```http
GET /api/positions/EURUSD
```

## SignalR

The backend exposes a SignalR hub at:

```text
/hubs/prices
```

The frontend subscribes to the following events:

```text
pricesUpdated
positionsUpdated
```

`pricesUpdated` is broadcast when the background price generator creates a new tick.

`positionsUpdated` is broadcast when positions exist and are recalculated against the latest prices.

## Redis Data Model

The app uses Redis as a fast in-memory store.

Common keys:

```text
price:EURUSD
price:GBPUSD
price:USDJPY
price:EURGBP

pricehistory:EURUSD
pricehistory:GBPUSD
pricehistory:USDJPY
pricehistory:EURGBP

quote:{quoteId}

trades
trade:{tradeId}

position:EURUSD
position:GBPUSD
position:USDJPY
position:EURGBP
```

### Price Keys

`price:{pair}` stores the latest price for a pair.

### Price History Keys

`pricehistory:{pair}` stores recent price ticks in a Redis list. The list is trimmed to keep only the latest ticks.

### Quote Keys

`quote:{quoteId}` stores temporary executable quotes. Quote keys expire automatically.

### Trade Keys

`trade:{tradeId}` stores trade details.

The `trades` list stores recent trade IDs for trade history retrieval.

### Position Keys

`position:{pair}` stores the latest net position and unrealized P&L for each pair.

## Trading Concepts Used

### Bid, Ask, and Spread

Each FX price has:

```text
Bid = price you can sell at
Ask = price you can buy at
Spread = Ask - Bid
```

Example:

```text
EURUSD bid = 1.08500
EURUSD ask = 1.08520
Spread = 0.00020
```

### Base and Quote Currency

For a pair like `EURUSD`:

```text
Base currency = EUR
Quote currency = USD
```

Buying `EURUSD` means buying EUR and selling USD.

Selling `EURUSD` means selling EUR and buying USD.

### Position Direction

A positive net base amount is a long position.

```text
+1,000,000 EURUSD = long EUR against USD
```

A negative net base amount is a short position.

```text
-1,000,000 EURUSD = short EUR against USD
```

### Unrealized P&L

The simulator uses a simplified P&L calculation:

```text
Unrealized P&L = Net Base Amount × (Current Price - Average Price)
```

P&L is displayed in the quote currency of the pair.

For example, EURUSD P&L is shown in USD.

## Risk Rules

The risk service currently applies two simple checks:

```text
Max single trade size: 2,000,000 base currency units
Max net exposure per pair: 5,000,000 base currency units
```

The simulator allows both long and short positions, which is common in institutional FX workflows.

## Known Limitations

This is a simplified simulator. Current limitations include:

- Prices are randomly generated and not connected to real market data.
- Redis is used as the main data store, so data is not durable unless Redis persistence is configured.
- There is no authentication or user separation.
- All users share the same simulated trading state.
- Risk checks are intentionally basic.
- P&L calculations are simplified and do not handle all real-world FX accounting cases.
- There is no real FIX connectivity or external liquidity provider integration.
