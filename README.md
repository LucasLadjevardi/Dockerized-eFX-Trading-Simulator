# Dockerized eFX Trading Simulator

A Dockerized electronic foreign exchange trading simulator built with **ASP.NET Core**, **React**, **SignalR**, **Redis**, **Nginx**, and **Docker Compose**.

The application simulates a simplified eFX workflow: live FX prices are generated by the backend, streamed to the frontend, quoted to the user, executed as mock trades, checked against basic risk limits, stored in Redis, and reflected in live positions and unrealized P&L.

This project is intended as a learning and portfolio project for understanding common concepts used in electronic trading systems. It is not connected to real markets and does not place real trades.

---

## Features

- Simulated live FX prices for common currency pairs
- Real-time price streaming with SignalR
- React dashboard with live price board and price chart
- Quote request workflow using bid/ask pricing
- Temporary executable quotes with Redis expiry
- Mock trade execution
- Trade history stored in Redis
- Position tracking by FX pair
- Unrealized P&L calculation
- Basic risk checks
- Dockerized frontend, backend, and Redis services
- Nginx frontend container with API and SignalR proxying
- Swagger UI for backend API exploration
- Optional CI/CD workflows for build validation and Docker image publishing

## Supported Currency Pairs

The simulator currently generates prices for:

- `EURUSD`
- `GBPUSD`
- `USDJPY`
- `EURGBP`

Currency pairs are interpreted using standard FX convention:

```text
EURUSD = EUR / USD
Base currency = EUR
Quote currency = USD
```

A trade amount is treated as the **base currency amount**.

Example:

```text
BUY 1,000,000 EURUSD at 1.0850
= buy 1,000,000 EUR
= sell 1,085,000 USD
```

## Architecture Overview

```text
React Frontend
    |
    | HTTP requests: quotes, trades, positions, history
    | SignalR: live prices and position updates
    v
Nginx Frontend Container
    |
    | /api/*   -> backend:8080/api/*
    | /hubs/*  -> backend:8080/hubs/*
    v
ASP.NET Core Backend
    |
    |-- PriceGeneratorService
    |-- QuoteService
    |-- TradeService
    |-- PositionService
    |-- RiskService
    |-- PriceHub SignalR hub
    v
Redis
```

The frontend is served by Nginx on host port `3000`. Nginx proxies API requests and SignalR WebSocket traffic to the backend service inside the Docker network.

The backend exposes REST endpoints and a SignalR hub. Redis stores latest prices, price history, temporary quotes, trades, and positions.

## Runtime Services

Docker Compose starts three services:

| Service | Description | Host Port |
|---|---|---:|
| `frontend` | React app served by Nginx | `3000` |
| `backend` | ASP.NET Core API and SignalR hub | `8080` |
| `redis` | Redis data store | `6379` |

## Setup

### Prerequisites

Install:

- Docker
- Docker Compose

You do not need to install .NET, Node.js, or Redis locally if running through Docker.

### Running the application

From the repository root, run:

```bash
docker compose up --build
```

Then open:

```text
Frontend: http://localhost:3000
Backend:  http://localhost:8080
Swagger:  http://localhost:8080/swagger
Health:   http://localhost:8080/health
```

To stop the application:

```bash
docker compose down
```

```http

```

Example request:

```json
{
  "pair": "EURUSD",
  "side": "BUY",
  "amount": 1000000
}
```

The amount is interpreted as the base currency amount. Buy orders use ask price. Sell orders use bid price.

GET /api/trades
```

### Positions

GET /api/positions

```

## SignalR

The backend exposes a SignalR hub at:

```text
/hubs/prices
```

The frontend subscribes to:

```text
pricesUpdated
positionsUpdated
```

`pricesUpdated` is broadcast when the background price generator creates a new tick.

`positionsUpdated` is broadcast when positions exist and are recalculated against latest prices.

## Risk Rules

The risk service currently applies simple checks such as:

```text
Max single trade size: 2,000,000 base currency units
Max net exposure per pair: 5,000,000 base currency units
```

The simulator allows both long and short positions, which is common in institutional FX workflows.

## Known Limitations

This is a simplified simulator. Current limitations include:

- Prices are randomly generated and not connected to real market data.
- Redis is used as the main data store, so data is not durable unless Redis persistence is configured.
- There is no authentication or user separation.
- All users share the same simulated trading state.
- Risk checks are intentionally basic.
- P&L calculations are simplified and do not handle all real-world FX accounting cases.
- There is no real FIX connectivity or external liquidity provider integration.
